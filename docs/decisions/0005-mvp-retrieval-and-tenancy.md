# ADR 0005：MVP 售后检索范围与多租户架构预留

- 状态：已确认（2026-11-18）
- 关联决策：[0001-product-form.md](./0001-product-form.md)

## 背景
第一版（MVP）需要尽快在试点工作室跑通「自动录屏 → 闲置上云 → 售后输入投诉定位时间点」核心闭环。如果首期同时铺开复杂游戏画面 OCR 和多模态视觉事件识别，会显著拉长研发周期并提高推理算力成本；另一方面，虽然首期仅服务试点工作室，但产品规划面向多家工作室共用，后期补改多租户隔离的返工成本极高。

## 决定
1. **MVP 售后检索范围（语音定位为主，缩略图辅助）**：
   - **一期（MVP）**：聚焦解决语言沟通、服务态度、口头承诺等核心纠纷场景。云端对双音轨分别执行静音过滤与 ASR 转写，叠加行业词表与拼音纠偏，结合自然语言投诉做混合检索（语义向量 + 关键词），并返回带**关键帧缩略图预览**的候选时间点列表，由售后人员点击播放器核对判断。
   - **二期演进**：在 MVP 闭环验证后，再逐步叠加游戏画面 OCR（结算面板、战绩、撤离状态）与多模态事件识别（如长时间画面静止挂机检测）。

2. **多租户隔离（全链路预留 `studio_id`）**：
   - 先服务试点工作室跑通业务，但从数据库 Schema、接口鉴权到对象存储目录结构全链路强制携带 **`studio_id`**。
   - 所有业务表以 `studio_id` 作为隔离字段和前导索引；对象存储路径统一以 `studios/{studio_id}/...` 隔离；所有查询与预签名访问链接均在服务端强制校验租户边界。

## 后果
- [requirements.md](../requirements.md) 中原 R8（画面结算/撤离/挂机识别）降级调整为二期目标，MVP 验收聚焦双音轨语音定位准确率与关键帧预览可用性。
- 试点期只需在库中初始化 1 个默认试点 `studio_id`，后续接入新工作室时无需迁移数据或重构权限模型。
