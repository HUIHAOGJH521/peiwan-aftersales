# ADR 0003：上传隐私策略与 MVP 订单关联

- 状态：已确认（2026-11-18）
- 关联决策：[0002-auto-recording.md](./0002-auto-recording.md)

## 背景
[ADR 0002](./0002-auto-recording.md) 确定检测到游戏启动即自动录屏，以防止漏录。但该机制在落地前需解决三个核心问题：
1. **隐私与成本**：自动录制会包含陪玩师非接单的私人对局，若全量自动上传会侵犯隐私并大幅增加云端存储与转写成本。
2. **游戏网络零干扰**：如果在游戏运行期间实时上传视频切片，会占用上行带宽，导致陪玩师游戏中跳 ping 或丢包。
3. **订单归档**：MVP 阶段尚未接入工作室外部派单系统，如何以最低交互成本将录像归档到对应接单记录。

## 考虑过的方案
### 上传与隐私策略
| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 全量自动上传，云端按时间人工打标 | 永不漏传 | 私人对局直接上云，隐私风险不可接受，存储与 ASR 成本高 |
| B. 仅点击接单时才开始录制 | 无私人录像 | 陪玩师一旦忘点「开始接单」，纠纷时彻底无据可查 |
| C. 本地全量兜底暂存 + 接单状态标记 + 闲置后台上传 | 既不漏录兜底，又确保私人局不上云且游戏期零带宽占用 | 客户端需维护本地缓存索引、切片物理隔离与 3 天清理机制 |

## 决定
1. **采用方案 C（本地全量兜底 + 接单标记上云 + 闲置后台上传）**：
   - **本地全量兜底**：游戏启动后自动录制并切片写入本地加密/隔离缓存目录；所有本地缓存默认保留 **3 天（72 小时）** 后自动滚动清理。
   - **接单状态切换与物理分段隔离**：陪玩师通过系统托盘或轻量小窗一键切换「开始接单 / 结束接单」状态。状态切换时客户端立即触发切片分段边界（Split），确保**接单时段切片**与**私人时段切片**在物理文件层面严格分离。
   - **仅接单时段自动入队**：只有处于「接单中」产生的切片才自动进入云端断点续传队列；私人局切片绝不自动上传。
   - **游戏零干扰上传**：后台上传器仅在**游戏进程退出后**或**系统空闲时**（无游戏运行）执行断点续传；检测到游戏运行中立即挂起上传，确保上行带宽零抢占（零跳 ping / 零掉帧）。
   - **漏点接单兜底补传**：若陪玩师忘点「开始接单」且 3 天内发生纠纷，陪玩师可在客户端本地记录中定位对应时段，经**本人显式确认授权**后手动将指定片段加入补传队列。

2. **MVP 订单关联（极简版）**：
   - 点击「开始接单」时支持**可选填写**订单号或备注（不填也可直接开始，不阻断操作）；「结束接单」后闭合为一条接单会话（Session）。
   - 云端按 **`(studio_id, player_id, start_time, end_time)`** 与可选订单号/备注进行归档与检索。
   - 二期再通过 API / Webhook 对接工作室派单系统。

## 后果
- 客户端需引入本地轻量状态库（SQLite）追踪接单会话、切片文件归属、上传进度与过期清理时间。
- 托盘图标与小窗需清晰区分「私人录制中（仅本地）」与「接单录制中（将上云）」两种视觉状态，保障陪玩师知情权。
