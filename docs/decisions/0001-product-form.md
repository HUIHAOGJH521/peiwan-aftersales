# ADR 0001：产品形态

- 状态：已确认（2026-11-17）
- 决定人：项目负责人

## 背景
陪玩售后纠纷需要录屏证据。最初设想是售后人员手动上传录屏，但很多陪玩师不会主动录，录了也可能没保存。

## 考虑过的方案
| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 只做售后网页，人工上传录屏 | 开发最简单 | 依赖陪玩师自觉录屏，出纠纷时常常没证据 |
| B. 陪玩电脑本地客户端，本地完成录制和分析 | 不依赖网络和服务器 | 实测 CPU 转写 26 分钟录屏需 6 分 25 秒且占满 CPU，打游戏时会掉帧 |
| C. 陪玩电脑轻量客户端只录制，云端分析，售后用网页查询 | 不影响游戏；证据自动留存 | 需要服务器、上传带宽、账号体系 |

## 决定
采用方案 C：
- **客户端**：后台常驻，只负责录制和上传，不做识别分析。
- **云端**：语音转写、画面识别、向量索引、检索。
- **售后网页**：输入投诉，返回可跳转的候选时间点，由人判断责任。
- 多家工作室共用，需要账号和工作室之间的数据隔离。

## 后果
- 客户端资源占用目标：录制时 CPU 平均不超过 3%，内存不超过 200 MB（待实测确认）。
- 需要处理上传失败、断网补传。
- 隐私和反作弊约束见 requirements.md 的安全红线。
