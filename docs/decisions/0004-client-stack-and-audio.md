# ADR 0004：客户端技术选型、反作弊隔离与双音轨采集

- 状态：已确认（2026-11-18）
- 关联决策：[0001-product-form.md](./0001-product-form.md)、[0002-auto-recording.md](./0002-auto-recording.md)

## 背景
客户端长期运行在 Windows 陪玩电脑上，需同时满足以下硬性约束：
1. **反作弊合规**：《三角洲行动》接入腾讯 ACE 反作弊系统，客户端任何可疑的进程读取或注入行为都可能导致陪玩账号封号。
2. **低资源占用**：录制期间目标 CPU 平均 ≤3%、内存 ≤200 MB，不能影响游戏帧数。
3. **复杂硬件兼容性**：部分陪玩电脑无独立显卡或硬编资源紧张，需有平滑降级手段。
4. **多人语音区分**：售后纠纷多围绕「谁说了什么、谁态度不好、谁做出过承诺」，混音单音轨在多人同时说话或游戏音效嘈杂时极易导致声纹混淆。

## 决定
1. **客户端技术栈**：
   - **主控与托盘 UI**：采用 **`C# (.NET 8)`** 构建 Windows 桌面托盘应用（含极简接单开关小窗），负责游戏进程监测、接单状态管理、本地缓存清理、空闲判断与后台断点续传调度。
   - **独立系统级录制/编码子进程**：主控按需拉起独立录制子进程，基于 Windows 原生多媒体接口：
     - 画面采集：**`Windows.Graphics.Capture` (WGC)**；
     - 音频采集：**`WASAPI`**；
     - 编码封装：**精简版 FFmpeg 硬件编码**（优先使用 NVENC / AMF / QSV，输出 `720p` 低码率视频切片）。
   - **无独显降级策略**：检测到无可用硬件视频编码器时，自动降级为「双音轨音频 + 低帧率关键截图序列」，避免 CPU 软编抢占游戏算力。

2. **反作弊安全红线**：
   - 游戏启停仅通过读取系统进程列表（进程名）判断。
   - 画面与音频采集全部走与 OBS 同类的系统公开接口。
   - **严禁**任何形式的 DLL 注入、API Hook、读取游戏内存、修改游戏文件或在游戏画面上方渲染 Overlay 叠加层。

3. **双音轨分离录制**：
   - 录制切片显式封装 **2 条独立音轨**（而非混成单声道/立体声）：
     - **音轨 1（Track 1）**：陪玩师麦克风输入（WASAPI Capture）。
     - **音轨 2（Track 2）**：系统播放回环声音（WASAPI Loopback，含语音软件中老板声音及游戏声音）。
   - 云端转写时分别对 Track 1 与 Track 2 独立执行 ASR，从数据源头天然区分「陪玩发言」与「老板/对端发言」。

## 后果
- 主控与录制子进程解耦，即使编码子进程因显卡驱动或游戏切换全屏异常退出，主控也可秒级自动拉起恢复，不丢失本地状态索引。
- 需处理 Windows 音频默认设备热插拔（如陪玩拔插耳机）时的 WASAPI 重连逻辑，并在文档/引导中提醒陪玩师勿开启系统「侦听此设备」以防双轨串音。
